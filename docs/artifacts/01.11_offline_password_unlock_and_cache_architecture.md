## 🎯 1. Executive Summary & Design Target

To achieve **100% offline productivity** on planes, remote islands, or during network outages **WITHOUT sacrificing flash drive / lost device security**, the extension implements a **Password-Derived Local Key Derivation Model (PBKDF2 + AES-GCM 256)**.

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                     OFFLINE ZERO-KNOWLEDGE UNLOCK LIFECYCLE                            │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ 1. INITIAL SETUP (Online):                                                            │
│    User enters ad.gov.sc email + password. Extension derives Master Key from password.  │
│    Local DB is populated with encrypted cache (FLE) + offline tokens.                  │
│                                                                                        │
│ 2. RE-OPENING OFFLINE (e.g. In Flight / Lost Network):                                 │
│    User launches Thunderbird -> Extension displays Secure Unlock Screen.               │
│    User enters correct password -> Master Key derived in RAM (never written to disk).  │
│    All cached tasks, notes, calendar events, and offline drafts unlock in RAM.         │
│                                                                                        │
│ 3. LOST FLASH DRIVE SCENARIO (Thief acquires USB):                                    │
│    Thief plugs USB into another laptop.                                                │
│    All IndexedDB records on the USB drive are AES-GCM ciphered blobs.                  │
│    Thief does NOT have user's password -> 0 data recovery possible.                   │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

## 🔐 2. Key Derivation & In-Memory Session Architecture

```
                 [ User Input: ad.gov.sc Password ]
                                │
                                ▼
                   [ Local Random Salt (16 bytes) ]

   [ Decrypt IndexedDB ]                  [ Queue Offline Actions ]

```

## ⚙️ 3. How Offline Operation Works Step-by-Step

### 3.1 Initial Setup & Salt Provisioning
1. During onboarding, when the user provides their `ad.gov.sc` password, the extension generates a unique cryptographic salt (`crypto.getRandomValues(new Uint8Array(16))`).
2. An **Auth Verification Tag** is generated: `AES-GCM(plaintext: "DICT_GOV_SC_VERIFIED", key: derivedKey)`.
3. The encrypted verification tag and salt are saved in `db.credentials`. The password itself is **NEVER saved to disk**.

### 3.2 Offline Authentication Check
1. When Thunderbird launches without an internet connection:
2. The user is prompted: `"Enter your domain password to unlock offline workspace"`.
3. The extension tests the entered password against the stored `Auth Verification Tag`.
4. **If Correct:**
   - The session key is instantiated in volatile RAM.
   - `DeltaStore.getTasksForAccount()` and `DeltaStore.getNotesForAccount()` seamlessly decrypt all cached records.
   - The user can read, search, edit, create new tasks, pin notes, and organize calendars with 0 latency.
5. **If Incorrect:**
   - Decryption fails immediately with an authentication error.
   - A rate limiter locks attempts after 5 failed tries (preventing brute-force on the flash drive).

### 3.3 Offline Action Queuing (`isDirty: true`)
Any change made while offline (creating a note, checking off a task, drafting an executive delegation invite) is saved to IndexedDB with:
* `isDirty: true`
* `updatedAt: Date.now()`
* `encryptedPayload: AES-GCM(newContent, sessionKey)`

When the network reconnects, the background alarm detects `navigator.onLine === true`, reads `DeltaStore.getDirtyRecords(sessionKey)`, and synchronizes everything upstream to Microsoft 365 and CalDAV in chronological order.

| Security Parameter | Standard Thunderbird Storage | Our Password-Unlocked FLE Model |
| :--- | :--- | :--- |
| **Offline Functionality** | ✅ Full offline access | ✅ Full offline access |
| **Data at Rest on USB** | ❌ Plaintext SQLite / Mbox files | 🔒 100% AES-GCM 256-bit Ciphertext |
| **Lost USB Vulnerability** | 🔴 Full leak of all emails & tasks | 🟢 Mathematically impossible without password |
| **Password Storage** | ❌ Often cached unencrypted or weak hash | 🔒 Zero password storage (PBKDF2 100k rounds) |
