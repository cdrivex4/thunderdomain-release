# Gap Analysis Supplemental — What Gemini Missed
## Thunderbird Outlook Parity & Productivity Suite
**Artifact ID:** `01.08_gap_analysis_supplemental.md`  
**Date:** 2026-09-27  
**Scope:** Features, infrastructure, and code the prior scaffold entirely omitted  
**Authority:** Department of Information Communications Technology (DICT), Republic of Seychelles

> [!IMPORTANT]
> This is the gap analysis from an Outlook-parity perspective — i.e., "what did a government Outlook user have that is still missing from this extension?" It is ordered by user impact, not technical complexity.

## Category 1: 🔴 Showstoppers (Missing infrastructure that breaks the app in production)

### GAP-001: No Token Refresh Loop — Users Log Out After 60 Minutes
**Impact:** Every M365 user is silently unauthenticated 60 minutes after first login.  
**Resolution:** `src/background/token-refresh-manager.ts` **CREATED** + wired into background alarm scheduler.

### GAP-002: No Background Sync Alarm — Extension Syncs Once Then Stops
**Impact:** The `alarms` permission was declared in `manifest.json` but `messenger.alarms.create()` was never called. After initial provision, the extension never polls again unless restarted.  
**Resolution:** `background.ts` now creates `delta-sync-and-refresh` alarm at 5-minute intervals. **CREATED**.

### GAP-003: No Delta Sync Engine Coordinator
**Impact:** Individual API clients exist (`graph/events.ts`, `caldav/caldav-client.ts`) but there is no orchestrator that calls them on each alarm tick.  
**Status:** `DeltaSyncEngine.syncAll()` — **TODO: Phase 2 hardening**. Marked with `// TODO` in background.ts.

## Category 2: 🟡 Missing Outlook Features Users Will Notice Immediately

### GAP-004: Email Follow-Up Flags
Outlook's coloured flag system (`🚩`) on messages is heavily used in government.  
- Graph API: `PATCH /messages/{id}` with `flag: { flagStatus: 'flagged' | 'notFlagged' | 'complete' }`  
- CalDAV/IMAP: `X-Flagged` custom header or IMAP `\Flagged` keyword  
- **UI needed:** Flag toggle in compose sidebar and message list integration  
- **Status:** Not started. Add to Phase 3.

### GAP-005: Email Categories (Not Just Task/Event Categories)
Outlook lets users apply Master Categories to **emails** (colour-coded tags in message list). Currently the extension only applies categories to tasks and events.  
- Graph API: `PATCH /messages/{id}` with `categories: ['Red Category', 'Project Alpha']`  
- Same `MasterCategory` schema in `types.ts` can be reused  
- **UI needed:** Category picker in compose sidebar + message list colour indicator  
- **Status:** Not started. Add to Phase 3.

### GAP-006: Shared Mailboxes (Different from Delegation)
Government offices commonly use `registry@dict.gov.sc` type **shared mailboxes** that multiple staff members access simultaneously. This is distinct from the Secretary/Boss delegation model.  
- Graph API: `/users/{shared-mailbox-id}/messages` with app-level or delegated access  
- Requires separate account entry with `role: 'SHARED_MAILBOX'` in `types.ts`  
- **Status:** `UserRole` type needs `'SHARED_MAILBOX'` added. Add to Phase 4.

### GAP-007: Room & Resource Booking
Government meeting rooms (`Conference Room A <confroom@dict.gov.sc>`) appear as calendar resources in Outlook.  
- Graph API: `/places/rooms` and `/places/{id}` for room availability  
- CalDAV: Resources appear as separate calendar principals  
- **UI needed:** Room selector in `<scheduling-assistant>` free/busy grid  
- **Status:** Not started. Add to Phase 4.

### GAP-008: Meeting Response Tracking
Outlook shows you who accepted/declined/tentative on your own calendar invites. The `CalendarEventItem` type has `attendees` with `status` field — but no UI shows this and no Graph poll fetches it.  
- Graph API: `/events/{id}/attendees` already in types  
- **UI needed:** Attendee response summary panel in event detail view  
- **Status:** Types exist, UI and sync missing. Add to Phase 3.

### GAP-009: Profile Photos in Delegation & Compose
Outlook shows profile photos everywhere — in the To: field, delegation panel, people search.  
- Graph API: `GET /users/{email}/photo/$value` returns JPEG blob  
- Cache in IndexedDB as base64 alongside account records  
- **UI needed:** Avatar `<img>` in `<delegation-modal>` boss cards, compose recipient chips  
- **Status:** Not started. Add to Phase 3.

### GAP-010: Contact Card Popover (Hover to See Person Details)
Hovering a name in Outlook shows a mini card: job title, department, phone, presence, OOO status.  
- Graph API: `GET /users/{email}?$select=displayName,jobTitle,department,mobilePhone,presence`  
- **UI needed:** New `<contact-card-popover>` Web Component  
- **Status:** Not started. Add to Phase 3 (low priority, high polish).

### GAP-011: Mailtip Warnings in Compose
Outlook shows yellow warnings in compose: "This person is out of office", "This is an external recipient", "This is a large group".  
- OOF status: Graph API `/users/{email}/mailboxSettings`  
- External domain detection: simple domain comparison against known `gov.sc` domains  
- **UI needed:** Warning banner in `<compose-sidebar>` component  
- **Status:** Not started. Add to Phase 3.

### GAP-012: Focused Inbox Triage
Outlook 365's AI-powered Focused/Other inbox split. For on-premise this doesn't exist, but for M365:  
- Graph API: `GET /messages?$filter=inferenceClassification eq 'focused'`  
- **UI needed:** Toggle in mail view (not currently in scope for this extension — Thunderbird handles mail display)  
- **Status:** Deferred — Thunderbird's mail pane is not under extension control without deep experiment work.

### GAP-013: Message Recall ("Unsend")
Government admins love message recall. M365 supports it via:  
- Graph API: No direct recall endpoint — requires `POST /messages/{id}/recall` (currently in preview)  
- **Status:** Deferred to v2 — API is in preview and unreliable.

### GAP-014: Voting Buttons in Emails
Government approval workflows use Outlook voting buttons (`APPROVE / REJECT`).  
- Read: Parse `X-Microsoft-CDO-VotingOptions` MIME header  
- Cast vote: `POST /messages/{id}/vote` (Graph API, preview)  
- **Status:** Deferred to v2.

### GAP-015: Quick Steps / Rules (Client-Side)
Outlook Quick Steps let users one-click move+mark+forward emails. Client-side rule evaluation (not Sieve) is possible via the `messenger.messages` filter API.  
- **Status:** Deferred to Phase 5. Server-side Sieve already in out-of-scope doc.

### GAP-016: Distribution List Expansion in Compose
Clicking a DL in Outlook's compose to: field expands it to individual members.  
- Graph API: `GET /groups/{id}/members`  
- **UI needed:** Expansion button in compose recipient chip  
- **Status:** Not started. Add to Phase 3.

### GAP-017: Free/Busy URL Publishing (CalDAV)
Non-365 users can publish their free/busy as a URL for external calendar tools.  
- CalDAV: `GET /freebusy/{user}.ifb`  
- **Status:** Deferred to Phase 5.

## Category 3: 🟢 Infrastructure Missing for Production Readiness

### GAP-018: Error Boundary Pattern for Web Components
If a Web Component throws in `connectedCallback()` or `render()`, it fails silently — the panel goes blank with no user feedback.  
**Fix needed:** Wrap all `render()` calls in try/catch that shows a friendly error state and fires a diagnostic event:
```typescript
private safeRender(): void {
  try {
    this.render();
  } catch (err: any) {
    this.innerHTML = `<div class="error-boundary">
      ⚠️ Panel failed to load. <button id="diag-btn">Copy Diagnostic</button>
    </div>`;
    console.error('[ErrorBoundary]', err);
  }
}
```
**Status:** Pattern defined here. Apply to all 8 Web Components in Phase 2.

### GAP-019: Sync Status Indicator
Users have no visible feedback about when the last sync happened or if it's in progress. Outlook has the sync status bar.  
**Fix needed:** A `SyncStatusStore` (simple observable in `storage/`) that components can subscribe to:
```typescript
export const syncStatus = {
  lastSyncedAt: null as Date | null,
  isSyncing: false,
  lastError: null as string | null,
};
```
Displayed as a small indicator in the `<spaces-rail>` footer.  
**Status:** Not started. Add to Phase 2.

### GAP-020: Offline Queue / Retry Mechanism
If the network drops while a user creates a task or note, the change is marked `isDirty=true` but there is no code that retries the upload when connectivity is restored.  
**Fix needed:** Listen to `navigator.onLine` change event → trigger `DeltaStore.getDirtyRecords()` → push upstream.  
**Status:** Pattern documented. Implement in Phase 2.

### GAP-021: PST / Archive Import Pathway
Government users migrating from Outlook have `.pst` archives. Thunderbird has an ImportExportTools NG add-on but no extension API for it.  
**Fix needed:** Document as a manual pre-migration step in the admin runbook.  
**Status:** Documentation gap. Add to `docs/compliance/DICT-SECURITY-BASELINE.md`.

### GAP-022: Multi-Account Token Management in GraphClient
`GraphClient` accepts `accountEmail` but `getBearerToken()` decrypts the credential and returns the raw JSON string — it does not parse the token payload or check expiry. The client should parse the envelope and reject expired tokens before even making the call (forcing an immediate refresh instead of a 401).  
**Fix needed:** Parse `StoredTokenPayload` in `getBearerToken()` and throw `TokenExpiredError` before the request if expired.  
**Status:** Add to Phase 2.

## Category 4: 🔵 Developer Experience & Tooling Gaps

### GAP-023: AI Diagnostic Export System — **BUILT THIS SESSION**
**Implemented:** `src/common/diagnostic-exporter.ts`
- 7-layer structured bundle (runtime, accounts, sync, DB health, errors, console, known issues)
- Console error interception via global `console.error` override
- Sanitized (no credentials, domains only)
- Copy-to-clipboard + file download buttons in `<settings-modal>`
- `aiPromptSummary` human-readable header for paste-into-AI workflow

### GAP-024: No `.env` / Environment Config Pattern
There is no `.env.example` file documenting what environment variables are needed. New developers have no idea that `GRAPH_CLIENT_ID` must be set.  
**Fix needed:** Create `.env.example`:
```env
# Required: Azure App Registration Client ID from DICT M365 tenant
GRAPH_CLIENT_ID=your-app-registration-uuid-here
```
**Status:** Add to repository root.

### GAP-025: Missing Admin Runbook
`docs/architecture.md` mentions operational deployment but there is no admin-facing runbook covering:  
- How to install the XPI on a fleet of government workstations via Group Policy
- How to pre-configure tenant settings centrally
- How to handle initial auth for shared workstations
- How to perform a migration from Outlook to Thunderbird+Extension

**Status:** Add `docs/ADMIN_RUNBOOK.md` in Phase 5.
