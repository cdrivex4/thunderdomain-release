## 🎯 1. The Threat Model: Lost Flash Drives & Portable Profiles

### 1.1 The Risk Scenario
A government officer or administrator installs portable Thunderbird onto an external USB flash drive or external SSD, connects their `ad.gov.sc` mailbox, downloads offline emails, tasks, and notes, and subsequently loses the USB drive in transit.

```
+-----------------------------------------------------------------------------------------------+
|                                      THREAT VECTORS ON A LOST USB                              |
+------------------------------------+--------------------------+-------------------------------+
| Component on USB Drive             | Risk Without Defense     | Mitigation Defense            |
+------------------------------------+--------------------------+-------------------------------+
| Extension OAuth & API Tokens       | Full Account Takeover    | 🔒 AES-GCM 256 Device Secret   |
|                                    |                          | (Bound to Workstation TPM/OS) |
+------------------------------------+--------------------------+-------------------------------+
| Extension Tasks & Notes            | Leakage of Gov Intel     | 🔒 Field-Level Encryption     |
| (IndexedDB tables)                 |                          | (Payloads ciphered at rest)   |
+------------------------------------+--------------------------+-------------------------------+
| Thunderbird Native Mail & MBOX     | Direct Plaintext Leak    | 🛡️ 4-Tier Defense Strategy   |
| (`ImapMail/`, `local.sqlite`)      |                          | (BitLocker2Go / Auto-Expiring)|
+------------------------------------+--------------------------+-------------------------------+
```

## 🛡️ 2. Four-Tier Defense Architecture

### Tier 1: Hardware-Bound Device Secrets (Implemented in `src/common/device-secret.ts`)
* The cryptographic passphrase used by `CryptoVault` is **never stored on the USB drive in plaintext**.
* The secret is generated on the host workstation via `crypto.getRandomValues()` and saved in `browser.storage.local`.
* **Consequence of Lost USB:** If an attacker plugs the USB into an external rogue laptop, the `_ds_v1` secret is missing or mismatched. The extension **fails to decrypt credentials, tokens, tasks, and notes**.

### Tier 2: Field-Level Encryption (FLE) at Rest (Implemented in `src/storage/delta-store.ts`)
* All Task descriptions, subtask titles, and Note HTML bodies are encrypted with AES-GCM 256-bit before being written to IndexedDB.
* In the raw database files on the USB drive, sensitive fields read `"[ENCRYPTED_AT_REST]"` and the actual data exists only as a ciphered envelope with a 128-bit authentication tag.

### Tier 3: Zero Local Body Caching Policy for Portable Profiles (Thunderbird Native Defense)
Thunderbird native IMAP mail storage (`ImapMail/`) can be configured via extension policy to **never store message bodies locally** on portable media:
1. **Headers Only (IMAP Synchronize Headers)**: Set `mail.server.default.autosync_offline_stores = false` and `mail.server.default.download_on_biff = false`.
2. Messages are rendered in-memory on demand over TLS 1.3 and discarded from RAM when the message tab closes.
3. No `.msf` or `.eml` bodies remain on the flash drive.

### Tier 4: BitLocker To Go / LUKS Removable Media Policy (DICT Mandate)
Per DICT Security Baseline:
1. **Windows 11 BitLocker To Go**: Government GPO policy `FDVEnforceUserCertProtect` enforces that any USB drive connected to an `ad.gov.sc` workstation must be formatted with BitLocker To Go encryption before write access is allowed.
2. **Auto-Purge Inactivity Guard**: Extension watchdog detects if the storage origin has changed or if the session has been idle for > 4 hours, forcing token evacuation and local cache purge.
